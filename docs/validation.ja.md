# 検証の範囲と再現性

[English](validation.md) | 日本語

コンテナ、候補選択、型付き解析、形状構築、現在状態との照合を分けて検証します。
取得した値や元バイト列の保持だけで、モデル全体を正しく解釈したとは判定しません。

公開サンプルの出典・ライセンス条件・サイズ・SHA-256 は
[部品マニフェスト](../fixtures/manifest.json)と
[アセンブリマニフェスト](../fixtures/assembly-manifest.json)にあります。
保留検証の割り当てもマニフェストで管理します。
関連するモデルや同一内容は独立したモデル系列として数えません。
CAD ファイル本体は取得スクリプトで入手し、Git や配布物には含めません。

## 検証結果

検証スクリプトは`internal/reports/latest/`へ詳細結果を出力します。
後述の集計コマンドは件数と状態を選び、`internal/reports/validation-summary.json`へ保存します。
比較記録・実行ログも同じ`internal/reports/`で管理し、ライブラリには同梱しません。
ある環境・依存バージョンの結果だけで、他のプラットフォームやInventorの現在状態を検証済みとは扱いません。

## 比較の種類

| 比較 | 確認できる内容 | 限界 |
| --- | --- | --- |
| 固定入力と固定した形状量 | 体積、面積、ソリッド数、境界箱の後退検知 | 同じ変換器に由来する比較値 |
| 円筒・直方体の解析式 | 寸法と mm 単位の体積・面積 | 複雑なモデルや現在状態のオラクルではない |
| olefile / Pillow | 対応する属性の値、PNG の独立展開 | 比較器の未対応を一致に含めない |
| ezdxf | SAB のレコード境界とタグ | 形状・保存状態の一致ではない |
| STEP / XDE 往復 | 階層、名前、配置、部品 RGB、形状量の維持 | Inventor native 状態・色の確認ではない |
| Apprentice / Inventor の取得値 | 同じ入力・状態で取得できた項目の独立比較 | 実機取得と出典が必要、未取得項目は未検証 |

固定した形状 baseline は回帰入力だけを含み、holdout を fitted baseline に追加しません。
新しい出典・モデル系列を保留にする方針はマニフェストで維持します。
入力不在、hash 不一致、テスト skip は成功扱いしません。

## 再現と任意のオラクル

FTC06（2021/2024）の円筒継ぎ目と CTC04（2021）のシェル閉鎖を検証する専用ゲートです。

```sh
python scripts/validate_analytic_closure.py
```

円筒継ぎ目とシェル閉鎖の検証実装を含む `cq-acis>=0.3.7,<0.4` および viewer の依存が必要です。
必要な変換器の診断項目がなければ明示的に失敗します。元の面の出典、全ての個別面、
閉じた主 body、STEP 往復、面を欠落させないメッシュ生成と viewer の動作を確認します。
FTC06 に含まれる二つの開いた補助平面 body は、個別プレビューと主ソリッドを分けて
報告し、ファイル全体のソリッド変換では引き続き拒否します。CTC04 は保存ソリッド
全体の変換と表示を必須にします。円錐頂点の法線はメッシュの UV 角度における解析的な
極限値を使い、頂点座標と三角形は変えません。現在の Model State やベンダーとの
同一性を示す検証ではなく、回帰入力だけを使用します。

FTC10/CTC02 のトリムゲートは通常CIで実行し、公開 cq-acis 0.3.8 以降にある
`cylinder_slit_faces` と楕円断面の診断項目を必要とします。

```sh
python scripts/validate_revolution_trims.py
```

FTC10（2021）は面1387の三つの往復辺を含む修正4面、CTC02（2021）は斜めの楕円断面6面を
検証します。STEP 往復で元の全頂点と辺数を保持し、メッシュに面が欠けないことを確認します。
未対応の曲線・曲面が残るため、部品全体の変換と自動3Dプレビューは引き続き拒否します。
cq-acis>=0.3.8,<0.4 を必要とします。個別面の成功は部品全体の対応を意味しません。
実測件数は生成されるレポートに記録します。

通常の再現手順は [開発ガイド](development.ja.md)、性能計測は
[ベンチマーク手順](../benchmarks/README.ja.md)を参照してください。

```sh
python scripts/summarize_validation.py --input internal/reports/latest --output internal/reports/validation-summary.json
```

このサマリー生成は必要な詳細結果が欠けていれば失敗します。
CI は同じ選択方式のサマリーだけを artifact にし、生の実行結果はアップロードしません。

Windows 上の `capture_vendor_oracle.py` は Apprentice から読み取り、
`capture_model_states.py` は Inventor 本体を使って入力のコピーで状態を切り替えます。
後者の保存はコピーに対して行い、状態切替・更新の成功を記録します。
`compare_state_candidates.py` は入力 hash と取得根拠が合う候補だけを比較します。
合成オラクルは比較パイプラインのテストであり、実機検証に数えません。
保存先には `internal/` 配下を明示してください。

図面の使い方と対応範囲は[IDWガイド](drawing.ja.md)を参照してください。
