# トレラント境界と有限 UV

[English](tolerant-trims.md) | 日本語

通常・fuzz の Rust 依存は公開 crates.io の `acis-core=0.3.5` と
`acis-py-bridge=0.3.5` です。検証時点では PyPI の 0.3.5 バージョン API が
404 のため、Python の互換要件 `cq-acis>=0.3.4,<0.4` と公開 0.3.4 のロックを
維持しています。以下は 0.3.5 ソースに未公開の変換修正を加えた結果です。
共有モデル API 2 は変更していません。

## 再現方法

```sh
python scripts/validate_components.py
python scripts/validate_topology.py
python scripts/validate_tolerant_trims.py
python scripts/validate_geometry.py
```

実ファイルのハッシュ、独立した holdout、固定済み形状指標を検査し、
`internal/reports/latest/` にレポートを出力します。トリム検証には読み込んだ
モジュール、元データの範囲とハッシュ、支持面の定義元、許容値と実測値を残します。
公開 0.3.4、0.3.5 のソース機能、今回の未公開機能を区別します。全体の成功には
実際の `Document.to_cadquery()` で全 258 面を保持する有効なソリッドを要求します。

## 残り4面への対応

| 面 | 対応 | 実測 / 上限（mm） |
| --- | --- | --- |
| 1164 | 保存 UV の厳密なノット分割と単調なパラメータ対応 | 0.006120595657 / 0.006130569677 |
| 2336 | 同じ方式で元の TEDGE 上限を維持 | 0.006099236931 / 0.006109190844 |
| 332、4351 | 頂点 3618 の保存座標を維持し、全3接続辺を検査 | 0.006526083452 / 0.006536083452 |
| 4351 | 支持面付き交線の保存 UV を独立の fit 上限で再パラメータ化 | 0.000748651878 / 0.001049799677 |

ノット挿入で保存 UV の軌跡と順序を維持し、各区間と曲線全体の 3D 誤差を検査します。
有限 UV 領域は広げず、領域外の投影曲線も採用しません。
`saved_pcurve_reparameterizations` に新旧ノットと誤差を残します。

頂点は ASM 22700 / 22601 の限定プロファイルです。flag 1、旧 scalar -1、
検査済み完全交線を持つ owner 辺、全接続辺の端点誤差を厳密に囲む2つの保存値を
要求します。過小・過大な値、接続辺を取り込む許容球、曖昧な接続は拒否します。
元の頂点座標と 3D 曲線は固定し、`tolerant_vertex_envelopes` に元の値と全接続辺を
記録します。TVERTEX 全般の仕様を保証するものではありません。

同じ検査済み支持面を参照する保存 UV fit は、自身の fit 上限で検査します。
3D fit は自身の上限で両支持面との誤差を別途検査します。頂点許容値を辺・UV や
TEDGE の上限に流用せず、モデル全体の分解能は 0.00001 mm のままです。

## ローカル検証結果（2026-09-13）

| 検査 | 修正前の 0.3.5 ソース | 今回の開発版 |
| --- | ---: | ---: |
| inline coedge のデコード | 10 / 10 | 10 / 10 |
| 有効なトレラント coedge 境界 | 206 / 206 | 206 / 206 |
| 有効な FTC07 個別面 | 254 / 258 | 258 / 258 |
| 有効な有限 UV 面 | 5 / 8 | 8 / 8 |
| FTC07 全体 | 拒否 | 有効な1ソリッド・258面 |
| 保存スプライン pcurve view | 224 | 224 |

33 ファイルのコーパスで有効なソリッド変換は11件（regression 10、holdout 1）です。
固定済みの既存形状指標を維持し、元の254面の面積も変わっていません。
FTC07 の体積は 1678794.5921294673 mm³ です。

これはローカルの保存形状の整合性と OCCT 妥当性の検証です。Inventor の現行
Model State、Windows/macOS、リモート CI は未検証です。今回の機能を PyPI 経由で
利用するには、cq-acis の次回公開と、その公開 wheel による再検証が必要です。
